# Linux で `ps` が使えない場合の対応

Linux のサーバーや最小構成のコンテナで `ps` を実行すると、`ps: command not found` になることがあります。これはコマンドを見つけられないという意味で、確認したいプロセスが停止していることを示すものではありません。

## コマンドの有無と OS を確認する

```sh
command -v ps
cat /etc/os-release
```

`command -v ps` がパスを返さなければ、パッケージが未導入か、実行ファイルの場所が `PATH` に含まれていない可能性があります。既にインストールされている場合は `PATH` も確認してください。

```sh
printf '%s\n' "$PATH"
```

## `ps` をインストールする

使用している Linux ディストリビューションに合わせて、次のコマンドを実行します。

| ディストリビューション | コマンド |
| --- | --- |
| Debian / Ubuntu | `sudo apt-get update && sudo apt-get install -y procps` |
| Fedora / RHEL 系 / Amazon Linux 2023 | `sudo dnf install -y procps-ng` |
| Alpine Linux（詳細な `ps` が必要な場合） | `apk add --no-cache procps` |

root で操作している場合は `sudo` を省略します。`sudo` 自体がない環境では、管理者権限で実行してください。パッケージの導入には、通常リポジトリへのネットワーク接続が必要です。

導入後は、プロセス一覧を表示できます。

```sh
ps aux
```

BusyBox 版などの簡易な `ps` では、対応するオプションが異なります。`ps aux` がオプションのエラーになる場合は、まず引数なしの `ps` を試してください。

## インストールせずに調べる

### コンテナの場合：ホストから確認する

Docker コンテナ内に `ps` がなくても、Docker を操作できるホストからプロセス一覧を取得できます。

```sh
docker top <container-name>
```

コンテナの停止や異常終了を調べる場合は、状態とログも確認します。

```sh
docker ps -a
docker logs --tail 50 <container-name>
```

`<container-name>` は対象のコンテナ名に置き換えてください。ホストに `ps` をインストールしても、コンテナ内に追加されるわけではありません。再作成後もコンテナ内で使いたい場合は、イメージのビルド時にパッケージを導入します。

### ネットワークサービスの場合：待受を確認する

`ss` があれば、TCP の待受と、そのソケットを使用するプロセスを確認できます。

```sh
sudo ss -ltnp
```

| オプション | 意味 |
| --- | --- |
| `-l` | 接続を待ち受けているソケットだけ表示 |
| `-t` | TCP を表示 |
| `-n` | アドレス・ポートを数値で表示 |
| `-p` | ソケットを使用するプロセスを表示 |

出力例（列の一部を省略）:

```text
LISTEN ... 0.0.0.0:8080 ... users:(("app",pid=327,fd=14))
```

この例では、`app` が TCP の 8080 番で接続を待っています。他ユーザーのプロセス情報を見るには管理者権限が必要な場合があります。

`ss` は待受を持たないプロセスの確認には使えません。また、コンテナ内で実行した場合は、そのネットワーク名前空間から見えるソケットを表示します。

### 基本ツールもない場合：`/proc` を確認する

Linux の `/proc` が利用できれば、シェルの組み込み機能で PID とプロセス名を列挙できます。

```sh
for entry in /proc/[0-9]*/comm; do
  if IFS= read -r name < "$entry"; then
    pid=${entry#/proc/}
    pid=${pid%/comm}
    printf '%s %s\n' "$pid" "$name"
  fi
done
```

実行中にプロセスが終了したり、アクセス権限がなかったりすると、読み取りエラーが出ることがあります。表示されるのは名前と PID で、完全なコマンドラインではありません。コンテナでは、その PID 名前空間から見えるプロセスに限られます。

## サービスの応答も確認する

プロセスの存在、ポートの待受、アプリケーションの正常動作は、それぞれ別の確認です。HTTP サービスなら、例えば次で応答を確認できます。

```sh
curl -I --max-time 10 http://localhost:8080/
```

ポートと URL は実際の設定に合わせます。これは HEAD リクエストなので、HEAD に対応しないサービスでは GET で確認します。

```sh
curl -sS --max-time 10 -o /dev/null -w '%{http_code}\n' http://localhost:8080/
```

期待するステータスコードやレスポンスはサービスの仕様に従って判断します。同じホスト内から接続できても、外部から接続できるとは限りません。必要に応じて、外部からの接続、ポート公開、ファイアウォール、経路も確認してください。
