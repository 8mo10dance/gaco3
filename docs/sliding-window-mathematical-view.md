# 尺取り法を「単調な境界探索」として捉える

尺取り法（sliding window / two pointers）は、`l` と `r` を経験則で動かす手法ではない。より本質的には、**区間の左右端を変数にした単調な真偽値の境界を、後戻りせずにたどる方法**である。

この見方を持つと、和・積で何が違うか、なぜ負数や `0 < x < 1` が難しいか、なぜ線形時間になるかを、同じ原理から説明できる。

## 1. 区間問題を2変数で定式化する

数列 `a[0...n]` の連続区間を、両端の添字 `(l, r)`（`0 <= l <= r < n`）で表す。区間が条件を満たすかを、述語（真偽値を返す関数）

$$
P(l,r)
$$

と書く。

たとえば「区間和が `k` 以上」なら

$$
P(l,r) \iff \sum_{i=l}^{r} a_i \ge k.
$$

「条件を満たす最短区間」を求める問題は、単に

$$
\min\{r-l+1\mid P(l,r)\}
$$

という2変数の最適化問題である。

ここで左端 `l` を固定し、そのとき条件を満たす最初の右端を

$$
f(l)=\min\{r\mid P(l,r)\}
$$

と定める（該当する `r` がなければ未定義とする）。すると各 `l` に対する最短区間の長さは `f(l) - l + 1` であり、答えは

$$
\min_l \bigl(f(l)-l+1\bigr)
$$

になる。

つまり最初に解くべき問いは「ポインタをどう動かすか」ではなく、**各 `l` に対する境界 `f(l)` は何か**である。

## 2. 高校数学の2変数最大・最小問題との違い

高校数学でも、2変数関数 `g(x,y)` の最大値は

$$
\max_{x,y} g(x,y)=\max_x\left(\max_y g(x,y)\right)
$$

のように、片方を固定して考える。尺取り法も問題の分解は同じである。

違いは **隣り合う内側問題の計算結果を再利用する**ことにある。素朴には `l=0,1,2,...` ごとに `f(l)` を最初から探すため、二重ループになりやすい。しかし `f(l)` 自体が単調なら、前の探索位置より左を調べ直す必要がない。

コード上では `l` と `r` が交互に動くように見えるが、交互に最適化しているわけではない。ずっと行っているのは、**連続してつながる境界関数 `f` を順に計算すること**である。

## 3. 単調性とは何か

単調性とは、入力をある順序で動かしたとき、出力が決まった向きにしか動かず、順序を壊さない性質である。

$$
x_1\le x_2 \Rightarrow h(x_1)\le h(x_2)
$$

なら `h` は単調非減少である。真偽値にも `false < true` という順序を入れれば、述語の単調性を同じように扱える。

尺取り法で重要なのは、典型的には次の2方向の性質である（ここでは「しきい値以上」を満たす最初の右端を探す場合）。

$$
\begin{aligned}
P(l,r)&\Rightarrow P(l,r+1)
&&\text{右へ伸ばしても OK を保つ}\\
\neg P(l,r)&\Rightarrow \neg P(l+1,r)
&&\text{左を削っても NG のまま}
\end{aligned}
$$

前者により、`l` を固定した一行は

```text
false false false true true true ...
                  ↑
                 f(l)
```

となる。後者により、その切り替わり位置は次の行で左へ戻らない。

## 4. なぜ $f(l) \le f(l+1)$ なのか

たとえば積について

$$
P(l,r) \iff \prod_{i=l}^{r}a_i\ge k
$$

を考え、すべての `a_i` が `1` 以上だとする。左端を一つ右にずらすと、

$$
\prod_{i=l+1}^{r}a_i
=\frac{\prod_{i=l}^{r}a_i}{a_l}
\le \prod_{i=l}^{r}a_i.
$$

ゆえに、`l` のときまだ条件を満たさなかった右端 `r` は、`l+1` にしても満たさない。すなわち `r < f(l)` なら `P(l+1,r)` も偽である。したがって `l+1` で最初に真になる場所が `f(l)` より左に来ることはなく、

$$
\boxed{f(l)\le f(l+1)}
$$

となる。

注意すべきなのは、各行で `r` に関して単調であるだけでは、この不等式は導けないことだ。`f` の単調性には、左端を動かしたときの単調性も必要である。

## 5. 和と積での成立条件

条件は「和」や「積」という演算の名前ではなく、区間を伸縮したときに必要な単調性が保たれるかで決まる。

| 集計値と典型問題 | 尺取り法が素直に使える条件 | 理由 |
| --- | --- | --- |
| 和 `<= k` の最長区間 | `a_i >= 0` | 右へ伸ばすと和は減らず、左を削ると和は増えない |
| 和 `>= k` の最短区間 | `a_i >= 0` | 右へ伸ばすと和は減らず、左を削ると和は増えない |
| 積 `<= k` の最長区間 | `a_i >= 1`（通常は正整数） | 右へ伸ばすと積は減らず、左を削ると積は増えない |
| 積 `>= k` の最短区間 | `a_i >= 1`（通常は正整数） | 同上 |

### `0` の扱い

`0` は積の除算更新をそのまま使えなくするため、別扱いにする。

- **積 `<= k` の最長区間**で `k >= 0` なら、`0` を一つでも含む区間の積は `0`。特に配列内に `0` があれば、配列全体の積も `0` なので、配列全体が答えになる。
- **積 `>= k` の最短区間**で `k > 0` なら、`0` を含む区間は決して条件を満たさない。したがって `0` ごとに配列を区切り、各「すべて1以上」の部分で探索すればよい。実装では窓をリセットする。

### 負数と小数への注意

- 和に**負数**が混ざると、右へ伸ばしたときに和が減ることがある。たとえば `10` が一時的に `k` を超えても、後ろの `-8` によって再び条件を満たすかもしれない。途中で区間を捨てる根拠がなくなる。
- 積に**負数**が混ざると、符号反転により大小関係が一方向に動かない。
- 積に `0 < a_i < 1` の**小数**が混ざっても同じである。`[10, 0.1]` の積は `10` から `1` へ減る。したがって、積の通常の尺取り法では「正」だけでは足りず、`1` 以上が必要である。

単調性が失われた問題には、累積和と二分探索、単調キュー、平衡木、DP など別の道具が必要になることが多い。

## 6. Ruby：和が `k` 以下の最長区間

要素が非負であると仮定する。`r` を一つ進め、条件を破った間だけ `l` を進める。各時点で窓は条件を満たす最長候補になっている。

```ruby
def longest_sum_at_most(a, k)
  left = 0
  sum = 0
  best = 0

  a.each_with_index do |x, right|
    sum += x

    while sum > k
      sum -= a[left]
      left += 1
    end

    best = [best, right - left + 1].max
  end

  best
end

p longest_sum_at_most([2, 1, 3, 5, 1], 6) # 3: [2, 1, 3]
```

途中に `a_i > k` があっても壊れない。その要素を含む窓が縮められ、最終的にはその要素自身も窓の外へ出る。問題なのは大きすぎる要素ではなく、負数である。

## 7. Ruby：積が `k` 以上の最短区間

ここでは `k > 0`、要素は非負整数とし、`0` 以外は `1` 以上とする。`0` では窓をリセットする。

```ruby
def shortest_product_at_least(a, k)
  raise ArgumentError, "k must be positive" unless k.positive?

  left = 0
  product = 1
  best = Float::INFINITY

  a.each_with_index do |x, right|
    if x.zero?
      # k > 0 では、0 を含む区間は条件を満たさない。
      left = right + 1
      product = 1
      next
    end

    product *= x

    # 今の right に対し、条件を満たす限り左を詰める。
    while product >= k
      best = [best, right - left + 1].min
      product /= a[left]
      left += 1
    end
  end

  best.finite? ? best : nil
end

p shortest_product_at_least([2, 3, 2, 5], 10) # 2: [2, 5]
```

この問題では、右端を伸ばして初めて `product >= k` になったら、その右端を固定したまま左端を進め、まだ条件を満たす限り短くする。`l` ごとの最初の OK を探すという定式化と一致している。

## 8. 2次元の単調述語と frontier

平面上の格子点 `(l,r)` に `P(l,r)` の真偽を書き込む。横軸を `r`、縦軸を `l` とし、`P(l,r)` を「和または積が `k` 以上」とするなら、典型的には次のようになる。

```text
                  r →
            NG NG NG | OK OK OK
            NG NG NG | OK OK OK
              NG NG NG NG | OK OK
                NG NG NG NG | OK OK
                  NG NG NG NG NG | OK
                         ↑
                      frontier
```

OK の集合は、区間を右へ伸ばす・左へ広げる方向に閉じている。このため NG と OK の間には、右または下へしか進まない階段状の境界（**frontier**）ができる。境界関数 `f(l)` は、この frontier を各行で表したものである。

尺取り法が走査するのは全 `n^2` 個の格子点ではない。**frontier だけ**である。これはより一般に、単調な2次元述語の境界探索と見なせる。

## 9. 水面・斜面の比喩

`P(l,r)` の値を地形の高さ、しきい値 `k` を水面だと思う。

```text
               r →
       高い: 条件を満たす（OK）
             █████████████
           ███████████████
         █████████████████
  ───────────────────────── 水面
       · · · · · · · · · ·
       低い: 条件を満たさない（NG）
                 l ↓
```

このとき `f(l)` は各 `l` において水面を越える最初の地点であり、尺取り法は水際を歩く操作に相当する。条件の向きを反転すれば、「ぎりぎり水に浸かっていない地点」を歩くと表現してもよい。本質は OK/NG の境界をたどることにある。

単調性は、地形に入り江や孤島がない保証だと考えられる。入り江がある（真偽が何度も反転する）なら、進んだ先で再び別の領域が現れるかもしれず、過去の探索範囲を捨てられない。

## 10. 二分探索との関係

`l` を一つ固定すると、`P(l,r)` が

```text
false false false true true true
```

の形なら、`f(l)` は二分探索で求められる。すべての `l` について行えば、典型的には `O(n log n)` である。

尺取り法はさらに `f(l) <= f(l+1)` を利用する。前の行で見つけた境界より左には次の境界がないので、二分探索を毎回やり直さず、その地点から水際を歩き続けられる。

> 二分探索は各行ごとに境界を探す。尺取り法は、行どうしの境界がつながっていることを利用して境界を追跡する。

## 11. なぜ `O(n)` になるのか

`left` は 0 から `n` までしか進まず、`right` も 0 から `n` までしか進まない。どちらも後戻りしないため、ポインタを動かす総回数は高々おおよそ `2n` 回である。

$$
O(n+n)=O(n).
$$

これは「内側の `while` があるのに線形時間」という見た目の疑問への答えでもある。`while` の反復は各外側ループで独立に `n` 回起きるのではなく、`left` を全体で合計 `n` 回しか動かさない。

## 12. 問題を見たときの確認順序

1. 区間 `[l,r]` が条件を満たすことを `P(l,r)` と書く。
2. 最長・最短などの目的を、`min` / `max` を用いた2変数最適化として書く。
3. `l` を固定したときの境界 `f(l)` を定義する。
4. 右端を伸ばす方向と左端を縮める方向で、真偽が一方向にしか変わらないか確かめる。
5. `f(l)` が単調になることを示せるなら、前の探索位置を再利用して尺取り法にできる。
6. できなければ、無理に2ポインタへ落とさず別の手法を検討する。

## 13. 学習の方向性

尺取り法を個別のテクニックとして暗記するより、次の連鎖として学ぶと応用が利きやすい。

$$
\text{2変数最適化}
\rightarrow
\text{単調述語}
\rightarrow
\text{境界関数}
\rightarrow
\text{frontier（境界）探索}
\rightarrow
\text{順序構造}
$$

アルゴリズムを数学的に理解する方向では、次の学習資源が相性よい。

- [MIT OpenCourseWare: Introduction to Algorithms (6.006)](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/): 問題のモデル化、正しさ、計算量を一体として学ぶ。

- [MIT Design and Analysis of Algorithms (6.046J)](https://ocw.mit.edu/courses/6-046j-design-and-analysis-of-algorithms-spring-2015/): 分割統治、DP、貪欲法などを設計原理として学ぶ。
